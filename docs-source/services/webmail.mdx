Roundcube is the browser-based webmail client deployed in SongketMail. It gives your users a familiar desktop-style mail interface — threaded conversations, an address book, drag-and-drop attachments, and a rich plugin ecosystem — all served from a PHP application container inside the secure `songketmail-net` cluster network. Roundcube talks to Dovecot for IMAP access and to Postfix for outbound sending, using the same virtual mailbox credentials stored in PostgreSQL. It runs unprivileged on internal port 8080 and is never directly reachable from the internet; all traffic arrives through the BunkerWeb WAF proxy, which terminates TLS and enforces HTTP security headers upstream.

## Access

Once your DNS record for your mail domain points to the host and BunkerWeb is running, you can reach the webmail interface at:

```text
https://<your-domain>/
```

Roundcube operates exclusively on **port 8080** inside `songketmail-net`. BunkerWeb proxies external port 443 to this internal endpoint. Direct access to port 8080 from outside the container network is not possible because the Quadlet does not publish port 8080 to the host — the only path in is through the proxy.

## Persistent Configuration

Roundcube stores two categories of persistent state on the host, each in its own bind-mounted directory.

| Host Path | Container Path | Contents |
|-----------|---------------|---------|
| `/var/srv/songketmail/roundcube/config` | `/var/www/html/config` | `config.inc.php` and any custom theme overrides |
| `/var/srv/songketmail/roundcube/db` | `/var/www/html/db` | SQLite session database (when not using PostgreSQL) |

Both directories are owned by UID/GID 2001 on the host thanks to `UserNS=keep-id:uid=2001,gid=2001`, so you can inspect and back them up without `sudo`.

## Connecting to Your Mail Server

Create `/var/srv/songketmail/roundcube/config/config.inc.php` (or edit the one generated by the container on first start) and set the IMAP and SMTP connection details to point at the correct internal container hostnames:

```php
<?php

// IMAP server — connect over STARTTLS to Dovecot inside the cluster network
$config['default_host'] = 'tls://songketmail-dovecot';
$config['default_port'] = 143;

// SMTP server — connect over STARTTLS to Postfix submission listener
$config['smtp_server'] = 'tls://songketmail-postfix';
$config['smtp_port']   = 587;
$config['smtp_user']   = '%u';
$config['smtp_pass']   = '%p';

// Session security
$config['des_key']         = 'change-this-to-a-24-char-secret!';
$config['product_name']    = 'SongketMail';
$config['session_lifetime'] = 10;
```

Using `tls://` instructs Roundcube to initiate a STARTTLS upgrade on the plain-text port rather than connecting with implicit TLS on port 993/465. Both Dovecot and Postfix inside `songketmail-net` present their internal certificates for this upgrade.

## Plugins

Roundcube ships with a set of bundled plugins. Enable them by adding their names to `$config['plugins']` in `config.inc.php`:

```php
$config['plugins'] = [
    'archive',
    'attachment_reminder',
    'carddav',
    'managesieve',
    'zipdownload',
];
```

| Plugin | Purpose |
|--------|---------|
| `archive` | Adds a one-click Archive button that moves messages to a dedicated Archive folder |
| `attachment_reminder` | Warns users before sending if the message text mentions an attachment but none is attached |
| `carddav` | Syncs the address book with a CardDAV server (useful if you run a contacts service alongside SongketMail) |
| `managesieve` | Exposes a GUI for creating Sieve server-side mail filtering rules via Dovecot's Sieve plugin |
| `zipdownload` | Allows users to download multiple selected messages or attachments as a single ZIP archive |

## Webmail Client Comparison

SongketMail defaults to Roundcube because its stateful architecture best fits an enterprise deployment where session persistence, address book sync, and a rich plugin ecosystem are required. The table below summarises how the main open-source candidates compare:

| Client | Architecture | Database Required | Security / 2FA | Performance |
|--------|-------------|-------------------|----------------|-------------|
| **Roundcube** | Server-side PHP (GPL-3.0+) | Yes (SQL) | Supported via plugins | Moderate — server-rendered |
| **SnappyMail** | SPA / client-side (AGPL-3.0) | No (stateless) | Native 2FA, hardened | Very fast, low memory |
| **RainLoop** | Legacy SPA (CC BY-NC-SA 3.0) | No | Outdated dependencies | Moderate — unmaintained |
| **Nextcloud Mail** | Heavy suite app (AGPL-3.0) | Yes | Native via Nextcloud | Very heavy, resource intensive |

<Note>
Roundcube was chosen over stateless alternatives such as SnappyMail because SongketMail's threat model prioritises server-side session isolation, persistent address books, and a battle-tested plugin ecosystem over raw client-side performance. Stateless clients like SnappyMail store credentials in the browser session and re-authenticate on every page load, which trades server load for a different security surface. If you are running SongketMail for a small team on constrained hardware and do not need plugin extensibility, SnappyMail is a viable drop-in replacement — swap the image in the Quadlet and update the BunkerWeb reverse proxy host accordingly.
</Note>

## Quadlet Container Configuration

```ini
[Unit]
Description=SongketMail Webmail Client Container (Roundcube)
After=network-online.target

[Container]
ContainerName=songketmail-web
Image=docker.io/roundcube/roundcubemail:1.6.8-apache
Network=songketmail-net
UserNS=keep-id:uid=2001,gid=2001
Volume=/var/srv/songketmail/roundcube/config:/var/www/html/config:Z
Volume=/var/srv/songketmail/roundcube/db:/var/www/html/db:Z
Environment=TZ=UTC
Label=fabric_cluster=songketmail
Label=service_type=web

[Install]
WantedBy=default.target
```

The Quadlet deliberately does not publish any host ports. The only way to reach Roundcube is through `songketmail-proxy`, enforcing that every request passes through BunkerWeb's WAF and TLS termination layer first.
