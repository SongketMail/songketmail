This repository includes pre-built static assets inside the docs/ directory and an automated deployment pipeline. You can choose to deploy your site using two methods: automated GitHub Actions or manual Direct Branch Deployment.

Method 1 Automated GitHub Actions Deployment (Recommended)

This repository includes a predefined, production-ready workflow in .github/workflows/deploy-pages.yml that builds and deploys your static pages securely and natively via GitHub Actions on every push.

1
Enable Workflow Permissions

Go to your GitHub repository -> Settings -> Actions -> General. Scroll to Workflow permissions, select Read and write permissions, and click Save.

2
Configure Build Source

Go to Settings -> Pages. Under Build and deployment, set Source to GitHub Actions.

3
Push to Trigger

Push any commit to main or master. Alternatively, navigate to the Actions tab, click Deploy GitHub Pages, and run the workflow manually.

Method 2 Direct Branch Deployment (`/docs` folder)

If you prefer not to use workflows and want GitHub to serve files directly from a static folder on your branch:

1
Push the Directory

Ensure the docs/ folder containing index.html is pushed to your default branch.

2
Configure Pages settings

Navigate to Settings -> Pages. Under Build and deployment, select Deploy from a branch as the Source.

3
Select Branch and Folder

Set Branch to your target branch (e.g. main), select the folder dropdown as /docs, and click Save.

Troubleshooting Tips

Site returns a 404 error?

Verify that your homepage is named exactly index.html (fully lowercase) and is directly inside the docs/ folder. Note that files/folders starting with underscores may be ignored by default unless a .nojekyll file is present.

Workflow fails with Permission Denied?

Check your Workflow permissions inside Actions settings. They must be set to Read and write permissions to allow the runner to push deploy artifacts.
