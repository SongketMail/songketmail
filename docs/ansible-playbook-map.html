🛠️ 1. Deployment: The site.yml Playbook

The principal deployment mechanism for the SongketMail cluster. It adopts the "Symmetric Privilege" pattern, executing system-level bootstrap procedures as root before performing unprivileged application orchestration.

A. Host Environment Preparation (Rootful Privilege)

  • Packages: Installs core system utilities alongside Podman 5 and the Podman-Docker bridge.
  • Low Ports: Sets net.ipv4.ip_unprivileged_port_start=25 allowing the rootless BunkerWeb container to bind public SMTP and HTTP ports.
  • Persistence Trinity Directories: Provisions 14 host-level directories under /var/srv/songketmail/ with 0700 owner-only access limits.

B. Quadlet Application Container Provisioning (Rootless)

  • Quadlet Generation: Translates playbook templates into native systemd user configuration files in ~/.config/containers/systemd/.
  • Session Management: Configures Alpine Alpine/Dbus system variables and enables services to run continuously across reboots with systemd session linger.

🛡️ 2. Security Operations: The Hardening Playbook

OS-level security hardening is managed via asimp_hardening_playbook.yml, integrating baseline policy validations alongside preventative break-prevention checks: 

# Pre-Remediation Safety Gate Check Block
- name: Verify no critical risk factors that would break the system
  ansible.builtin.assert:
    that:
      - asimp_risk_level not in ['CRITICAL_RISK', 'HIGH_RISK']
    fail_msg: "Pre-Remediation Safety Check failed: High risk of system breakage detected. Aborting!"

By validating SSH key status, listening ports, and filesystem availability, the playbook safely drops back to simulations (Audits) in unprivileged containers/Google Jules sandboxes.

📊 3. Monitoring, Telemetry and Multi-OS Verification

Diagnostic pipelines are triggered through Ansible playbooks to preserve engineering transparency:

  • Continuous Integration (CI/CD): playbooks/matrix_test.yml spins up sandboxed environments (Debian, AlmaLinux, Ubuntu) locally on the engine to verify that updates don't trigger package or systemd configuration crashes.
  • Developer Feedback Loop: wsl_feedback_playbook.yml (gated strictly to development execution contexts) reads local Podman configurations and routes structured reports directly to developers via active Jules remote sessions and GitHub comment APIs.
