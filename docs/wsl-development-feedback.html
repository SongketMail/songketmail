💻 WSL Ubuntu 26.04 Development & Jules Feedback Loop

1. Executive Summary & Intent

To expand testing beyond the unprivileged Google Jules container sandbox, developers can run full local test environments on Windows Subsystem for Linux (WSL) running **Ubuntu 26.04 (Noble/Plucky)**. This framework enables testing the entire 7-service decoupled email fabric with Podman 5+ under a real systemd service environment, automatically fetching tasks from Jules, and piping debugging output back to both Jules and the active GitHub PR.

⚠️ Development Only Warning: This harness is strictly intended for local testing and developer feedback loops. It is bypassed automatically for regular users to prevent any unauthorized API calls or environment conflicts.

⚙️ 2. WSL & Podman 5+ Configuration

Follow these simple steps on your local WSL instance to prepare it for development testing:

Step 1: Enable Systemd in WSL

# In /etc/wsl.conf:
[boot]
systemd=true

Step 2: Install Podman 5+

sudo apt update && sudo apt install -y podman podman-docker jq curl git ansible

Step 3: Setup SubUID/GID Namespace Mapping

sudo useradd -u 2001 -g 2001 -m -s /bin/bash songketmail || true
echo "songketmail:100000:65536" | sudo tee -a /etc/subuid
echo "songketmail:100000:65536" | sudo tee -a /etc/subgid

🔄 3. The Jules CLI and GitHub API Loop

The integrated loop fetches task definitions and pipes the result directly back to our active integration nodes.

  • Jules CLI Integration: The runner queries task details using jules task show or via the Jules REST endpoints.
  • Error Logging: Output dumps and detailed container logs are captured on failures and packed into structured formats.
  • GitHub PR Feedback: The playbook uses curl to POST comments directly to the active issue/PR timeline under the developer's credentials.
