🔒 Part 25: Email Security from the Wire to the Mailbox, JMAP & ACME Management

🔒 1. Executive Summary & Security Philosophy

Security in SongketMail is a core architectural default: Security is a default, not an add-on. The platform protects email communication across its entire lifecycle: from the wire to the mailbox.

  • Security as Default: All transports enforce TLS encryption, cryptographic identity checks, and strict authentication policies out-of-the-box.
  • Wire Security: In-transit mail stays encrypted and verified end-to-end with DANE, MTA-STS, and TLS Reporting (TLSRPT).
  • Automated Certificate Lifecycle: TLS certificates renew automatically over ACMEv2 (RFC 8555) via Let's Encrypt or an internal Smallstep Certificates (step-ca) Private CA server.
  • Zero-Trust Mailbox Encryption at Rest: Mailboxes stored on disk can be encrypted using the user's own S/MIME certificate or OpenPGP key. Storage operators or system admins with disk access cannot read mailbox contents without the user's private key.
  • Modern Web API Access (JMAP): Replaces legacy IMAP with the JSON Meta Application Protocol (JMAP / RFC 8620 & RFC 8621) over HTTP/2 and HTTP/3.
  • Memory Safety & Independent Audits: Core protocol components leverage Rust to eliminate memory-corruption vulnerabilities, validated by independent security audits.

🌐 3. Strong Transport Security: DANE, MTA-STS & TLS Reporting

3.1 DANE (DNS-based Authentication of Named Entities)

DANE utilizes DNSSEC to publish TLSA records in DNS, securely binding domain MX hostnames directly to expected TLS certificates or public keys.

Standard: RFC 6698 / RFC 7672 — Prevents MitM attacks and compromised CA certificate spoofing.

3.2 MTA-STS (SMTP MTA Strict Transport Security)

Enforces strict TLS connections for incoming mail streams. Published via DNS TXT _mta-sts.songketmail.internal and served over HTTPS at https://mta-sts.songketmail.internal/.well-known/mta-sts.txt.

Standard: RFC 8461 — Mode: enforce, max_age: 604800s.

3.3 TLS Reporting (TLSRPT)

Enables automated diagnostic feedback from sending relays regarding transport failures or policy violations via DNS record _smtp._tls.songketmail.internal.

Standard: RFC 8460 — Daily aggregate report feedback.

🔑 4. Automatic TLS Provisioning via ACMEv2 & Smallstep CA

Automated certificate management eliminates service downtime caused by expired SSL/TLS certificates.

Smallstep Certificates Integration (smallstep.com/certificates)

SongketMail includes a private certificate authority (X.509 & SSH) and embedded ACME server powered by Smallstep (step-ca). This enables automated internal TLS certificate issuance and renewal across all Podman Quadlet containers, combined with Single Sign-On (SSO) for SSH access.

  • Wildcard Certificate Support: Secure base and subdomains (*.songketmail.internal) via DNS-01 challenge.
  • TLS-ALPN-01 Support: Secure validation over HTTPS port 443 without open port 80.
  • HTTP-01 Challenge: Automated web server challenge verification.

🔐 5. Zero-Trust Mailbox Encryption at Rest (OpenPGP & S/MIME)

To guarantee mailbox privacy against untrusted storage providers or operator disk access, SongketMail provides server-side public-key encryption at rest:

OpenPGP Encryption

Incoming email payloads are encrypted with the user's uploaded OpenPGP public key before writing to disk or RustFS S3.

S/MIME Encryption

Supports X.509 S/MIME certificates for enterprise compliance, ensuring messages are encrypted end-to-end to the recipient's maildir.

⚡ 6. JSON Meta Application Protocol (JMAP - RFC 8620 & RFC 8621)

JMAP is a modern open standard used to synchronize data like email, calendars, and contacts between devices and servers using fast, lightweight web APIs (ports 443 / 8443).

How JMAP Works & Benefits

Uses JSON over HTTP to fetch and sync data efficiently in a single request, replacing noisy multi-step IMAP protocol commands.

  • Faster Performance: Synchronizes email, address books, and calendars in batch requests.
  • Lower Battery Consumption: Minimizes mobile radio wakeups compared to IMAP polling.
  • Developer Friendly: Simple JSON data models for mobile and web apps.
  • Learn More: Specifications available at JMAP.io.

🛡️ 7. Granular ACLs, Rate Limiting, DKIM Automation & Rust Memory Safety

  • Automated DKIM Lifecycle: Rspamd handles 2048-bit RSA/Ed25519 key generation, scheduled 90-day rotations, and automated DNS TXT record exports.
  • ACLs, Rate Limiting & Banning: BunkerWeb WAF and Rspamd enforce connection rate limits and automatic IP banning.
  • Memory-Safe Architecture in Rust: Core storage (RustFS) and JMAP engines are written in Rust, mathematically preventing memory corruption vulnerabilities.
  • Independently Security-Audited: Verified against CIS benchmarks and OWASP guidelines.
