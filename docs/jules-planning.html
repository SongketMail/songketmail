📋 Google Jules Operational Plan: DockPod Integration

This operational document provides a highly structured, multi-session tactical roadmap for **Google Jules** (and subsequent autonomous agent sessions) to safely deploy, configure, and verify DockPod within SongketMail's unprivileged user context.

Session 1 Environment Prep & Socket Activation

Objective: Ensure unprivileged session persistence and expose rootless Podman API socket.

  1. Enable systemd lingering: loginctl enable-linger songket.
  2. Set user environments: export XDG_RUNTIME_DIR="/run/user/2001".
  3. Enable the socket: systemctl --user enable --now podman.socket.
  4. Verify access permission on /run/user/2001/podman/podman.sock.

Session 2 DockPod Service Provisioning

Objective: Download, configure and start the unprivileged DockPod daemon as a systemd user service.

  1. Download stable executable binary to ~/.local/bin/dockpod.
  2. Write declarative systemd service unit: ~/.config/systemd/user/dockpod.service.
  3. Define environment configurations binding to localhost IP address 127.0.0.1 to block public exposures.
  4. Reload systemd user daemon and start service: systemctl --user enable --now dockpod.service.

Session 3 Nginx SSL/TLS Ingress Configuration

Objective: Route external requests to the locally bound panel and MCP endpoints safely through SSL/TLS proxies.

  1. Create a virtual host proxy blocks under Nginx directories pointing to 127.0.0.1:8080 (Web UI).
  2. Isolate Server-Sent Events (SSE) buffering by routing mcp.songketmail.local requests directly to 127.0.0.1:8090.
  3. Verify and hot-reload Nginx routing inside the unprivileged container pod.

Session 4 Security Hardening & Token Generation

Objective: Secure API authentication credentials and drop direct public ports exposure.

  1. Run firewall configuration dropping direct public traffic to ports 8080 and 8090.
  2. Register the primary admin user with high-entropy passwords.
  3. Generate a Bcrypt-hashed API key starting with dp_mcp_ from Settings.

Session 5 Agentic Verification Workflows

Objective: Register the MCP Server inside the Google Jules workspace and execute diagnostic audits.

  1. Bind mcp-remote parameters matching the proxy headers and authorization token.
  2. Perform live LLM inquiries checking container lists and log tails dynamically.
  3. Document and audit standard memory footprint values to confirm success.
