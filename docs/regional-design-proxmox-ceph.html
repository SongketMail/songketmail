🌐 Geolocated Regional Data Center Design

This document details the technical design, architectural patterns, and systemic improvements for the SongketMail Regional Data Center Infrastructure.

🗺️ 1. Multi-Region Geodistributed Topology

The core architecture consists of three geographically isolated regional data centers communicating over secure, dedicated low-latency Wide Area Networks (WAN).

1.1 Regional Characteristics

Details about Region Alpha, Region Beta, and Region Gamma.

🏛️ 2. Generalized Node Architecture (Per Region)

Each regional node abstracts physical hardware dependencies into standardized, enterprise-grade compute, security, and storage building blocks.

2.1 Hardware Sizing & Refinement

Compute, Security, Networking, Backup, and AI details.

🗄️ 3. Dual-Tier Ceph Storage Strategy

Balancing local hyper-converged low-latency VM disks (Tier 1) with external AlmaLinux-managed independent Ceph clusters (Tier 2).

3.1 Tier 1: Local Hyper-Converged Ceph (Proxmox-Managed)

Managed via native Proxmox VE (pveceph).

3.2 Tier 2: External Independent Ceph (AlmaLinux-Managed)

Sourced from the CentOS Storage SIG Repository.

🔗 4. External Ceph Visibility Inside Proxmox VMs

Answering the critical design question: Can the external Ceph cluster be seen and consumed directly by a Virtual Machine running inside Proxmox?

Approach A: Hypervisor-Mediated Virtualization (Storage.cfg)

Mapping external Ceph as a native storage pool in PVE.

Approach B: Guest-Native Direct Storage Protocol Access

Mapping RBD and CephFS mounts directly inside the VM.

Approach C: S3-Compatible Object Storage Gateway (Ceph RGW)

Accessing storage via RESTful RGW S3 APIs.

🚀 5. Architectural Improvements & Hardening Recommendations

Recommendations on Chrony Geolocation, MTU Tuning, Network Ring Fencing, and LACP Bonding.
