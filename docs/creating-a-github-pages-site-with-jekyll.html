🌐 Creating a GitHub Pages Site with Jekyll

Why Use Jekyll for GitHub Pages?

Jekyll is a blog-aware, static site generator written in Ruby that integrates natively with GitHub Pages. With Jekyll, you can publish documentation, portfolios, and websites directly from your markdown source files. It eliminates the need for database administration, provides incredible loading speeds, and guarantees robust security under static site immunity.

🛠️ Step 1: Install Prerequisite Tools

Before you can run Jekyll locally, make sure your host machine has Git, Ruby, and Bundler installed.

Verify Git Installation
git --version
Install Ruby & Compiler Packages (Debian/Ubuntu)
sudo apt-get install ruby-full build-essential zlib1g-dev
Install Bundler and Jekyll Gem
gem install jekyll bundler

📂 Step 2: Initialize Your Jekyll Site

You can initialize a Jekyll site in a completely brand new repository or inject it into an existing repository.

Case A: Creating a Site in a New Repository

mkdir my-jekyll-site
cd my-jekyll-site
git init
jekyll new . --force

Case B: Injecting Jekyll into an Existing Repository

If you already have a repository and want to serve files from a custom folder (like /docs), create _config.yml, Gemfile, index.md, and .nojekyll inside that folder manually.

⚙️ Step 3: Configure Gemfile & _config.yml

Configure the standard github-pages gem bundle to ensure your local site matches GitHub's remote builder environments.

Gemfile
source "https://rubygems.org"

gem "github-pages", group: :jekyll_plugins
_config.yml
title: "SongketMail :: LAB"
theme: jekyll-theme-primer
markdown: kramdown
exclude:
  - Gemfile
  - Gemfile.lock
  - vendor/

🖥️ Step 4: Local Testing & Building

Run the following bundler commands to fetch assets, resolve plugins, and launch the development server locally. 

# Install the specified gems
bundle install

# Run local development server
bundle exec jekyll serve

By default, Jekyll will build your site and launch a local web server at http://localhost:4000/. It watches for file saves and hot-reloads instantly.

⚠️ Step 5: Liquid Template Escaping

Because Jekyll is powered by the Liquid templating engine, any code blocks containing Jinja2 syntax (e.g. {{ ... }} or {% ... %} in Ansible files) will trigger compile-time exceptions.

💡 Solution: Wrap with raw / endraw Tags

Wrap any Jinja2 blocks inside {% raw %}{% raw %}{% endraw %} and {% raw %}{% endraw %}{% endraw %} template tags. This tells Liquid to skip processing the block and output the exact text natively.
