🛰️ Distributed Node Strategy

To support production-level horizontal scaling, high availability, and localized file execution, the fabric enforces a unique architectural concept called the Persistence Trinity.

📐 The Persistence Trinity

1. Quadlet Orchestration

Avoids legacy docker-compose or run scripts. Uses native Podman Quadlets for unprivileged user-level systemd integration, guaranteeing container recovery on host boot.

2. Storage Sovereignty

Solves the rootless UID mapping problem. Standard setups map internal container processes to random host UIDs. By enforcing keep-id, host processes match the container precisely!

3. Fabric Isolation

Isolates all containers and networks by prefixing them with skm_fabric_, permitting multiple isolated structures to run alongside each other seamlessly.

Why keep-id? The Storage Mapping Solution

In conventional rootless container execution, internal users like UID 2001 get remapped on the host to massive, arbitrary ranges (e.g., 101000). When backing up or executing audits directly on the host, the files appear as belonging to nobody:nogroup. By specifying UserNS=keep-id:uid=2001,gid=2001 at the Pod level, we align Host and Container permissions natively without needing root or sudo.

🔒 Security Architecture

Aligned with standard hardening frameworks and the ASIMP (Ansible System Integrity Management Platform) directives:

  • ✔
    Rootful Host-Level Tuning Ansible performs system-level optimizations (e.g. kernel limits, vm.max_map_count, bridge configurations, lingering) in the preparation phase.
  • ✔
    Strict Rootless Execution Services (SMTP, IMAP, Spam control) execute under the unprivileged, non-sudo system user songketmail (UID/GID 2001).
  • ✔
    System Integrity & Security Audits Automated scanning integrated inside execution playbooks verifying host setups with Lynis, OpenSCAP, and Debsums.

🚀 Deployment Guide

Prerequisites

  • Podman: Version 5.0.0 or higher is required on all target nodes.
  • Ansible: Version 9.0.0 or higher is recommended.
1 Configuration Check

Review global parameters in group_vars/all.yml to ensure correct subnetting and volume locations:

cluster_prefix: "skm_fabric"
songketmail_uid: 2001
storage_base_path: "/opt/songketmail"
2 Update Inventory

Add your remote hosts and target server IPs inside the inventory configuration:

[email_servers]
node1.songketmail.internal ansible_host=10.0.1.11
node2.songketmail.internal ansible_host=10.0.1.12
3 Run the Playbook

Deploy, optimize, and launch all the container instances via a single execution:

ansible-playbook -i inventory/hosts.ini site.yml

🛠️ Service Maintenance & Auditing

Because Storage Sovereignty is guaranteed by our unique keep-id setup, backup processes, maintenance operations, and auditing protocols are simplified. They execute under the non-sudo songketmail user seamlessly:

# View Postfix logs or mail queues directly from the host storage
ls -lh /opt/songketmail/emailserver/node1.songketmail.internal/data/
# Verify running rootless systemd services for our fabric
systemctl --user status skm_fabric_emailserver
systemctl --user status skm_fabric_pod-pod
